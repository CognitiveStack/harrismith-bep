## 5. The seven authorised questions

Ask exactly these. Do not reword, broaden or combine them.

### PPQ-001 — PM-1 / OC-A

> *"Using read-only listing operations only, enumerate the visible top-level
> areas of the Harrismith Fire Station project and their child folders to a
> depth of three levels. For each, report the exact visible name as displayed
> and the exact observed path. Report only what is listed; report nothing about
> intended use, suitability or governance."*

**Prohibited inference.** **A visible area or folder is not the governed
publication location.** An area named after an information state is evidence of
naming only. **No enumerated structure is selected, preferred or recommended by
being listed.**

### PPQ-002 — PM-3 / OC-D

> *"For each item version in the controlled observation sample defined by
> ROA-001, report the exact file extension and, where the tooling exposes it,
> the source file type and any derivative or translated output formats listed
> for that version. Do not request, trigger or download any translation, export
> or file content."*

**Prohibited inference.** **An observed file format is not an approved
publication format**, and a derivative output is not evidence of an approved
deliverable form. **The format information currently exists in does not
determine the format anything may later be published in.**

### PPQ-003 — PM-4 / OC-B

> *"For each item version in the controlled observation sample defined by
> ROA-001, report the exact name of every metadata field returned by read-only
> inspection and, for each field, the exact current value as returned or an
> explicit indication that it is empty. Report field names exactly as returned,
> without normalising, translating or grouping them."*

**Prohibited inference.** **A metadata field visible in the live environment is
not automatically required publication metadata**, and a populated field is not
evidence that its value is governed, checked or correct. **What must be carried
is a governance requirement; what is available is a platform fact.**

### PPQ-004 — PM-5 / OC-D

> *"Report which operations the available Autodesk connector exposes, classified
> as read-only or state-changing, listing each by its exposed operation name. Do
> not invoke any state-changing operation, including for testing. Where the
> connector or its documentation states a pre-condition, constraint, or
> operation that is unavailable or prevented, report that statement exactly as
> given."*

**Prohibited inference.** **An available upload or version-creation action is
not an approved upload procedure.** Its existence is neither permission to use
it nor evidence its use would be authorised. **A prevented operation is a
technical limitation, not a governed prohibition.**

### PPQ-005 — PM-6 / OC-C

> *"For each item version in the controlled observation sample defined by
> ROA-001 — none created by this observation — report the version-identifying
> and integrity-related attributes returned by read-only inspection, including
> version number, creation timestamp, file size, any checksum or hash field, and
> any approval-status field. For each, give the exact field name and value, or
> an explicit indication that the field is not returned."*

**Prohibited inference.** **A visible verification-related field is not an
approved verification requirement**, and an approval-status field is not
evidence that any approval, authorisation or verification occurred. **No upload
is performed to create this observation.**

### PPQ-006 — PM-7 / OC-D

> *"For one item in the controlled observation sample that has at least two
> visible versions, report the read-only relationships the tooling exposes
> between its successive versions and any exposed capability for replacing,
> superseding, archiving, withdrawing or removing a version or item — by exposed
> operation or field name only, without invoking any of them. Report whether
> previous versions remain listed and retrievable in version history."*

**Prohibited inference.** **A technical supersession, archive or delete
capability is not an approved supersession or withdrawal route**, and its
absence is not a governed prohibition. **That previous versions remain listed is
not evidence that a retention rule exists or is governed.**

### PPQ-007 — PM-3, PM-5, PM-7 / OC-D

> *"Where PPQ-002, PPQ-004 or PPQ-006 could not be answered, report for each the
> exact request attempted, the exact error, empty result or refusal returned,
> and whether the connector reported the operation as unavailable, unauthorised
> or unsupported. Report the limitation exactly as encountered, without
> substituting an explanation for why it occurred."*

**Prohibited inference.** **Inability to observe a fact is not observation that
the fact is absent, unavailable or prohibited.** A refusal is evidence about the
tooling, not about the project. **An "unauthorised" response is a platform-access
fact and establishes nothing about governance authority.**

### Not asked — PM-2

**No question asks who the publication owner is.** Publication owner,
publication/exchange authority, recipient acceptance authority, an authorised
uploader and an authorised approver are **outside this observation entirely**.

**Do not answer PM-2 indirectly.** Membership, folder ownership, permissions,
administrative access and previous activity are **not** routes to it. If such a
fact appears incidentally, record it as a plain platform fact and state that it
**establishes no authority**.
