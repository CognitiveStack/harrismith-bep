# Module 2 — Slide-to-Visual Map

**Status:** Working map for the Slides 1–14 content baseline. **Not governance.**

The **five-second read** column is the test that matters: if the audience cannot
take that away from the visual alone while the presenter is still speaking, the
visual is doing too much.

---

## 1. Column definitions

| Column | Meaning |
|---|---|
| **Primary visual** | The slide's principal visual source |
| **Optional support** | A second element, used only if time and space allow |
| **Type** | `diagrammatic` · `tabular` · `documentary` (a controlled-document extract) · `layout` (a composition specification) |
| **Five-second read** | What the audience should take from the visual alone |
| **Omit** | Detail that must not reach the final slide |
| **Speaker needed?** | Whether the visual is self-explanatory or depends on commentary |
| **Repo-only?** | Whether the slide is deliverable from repository source alone |
| **Mandatory warning** | The build requirement that must not be dropped |
| **Likely overclaim failure** | The specific wrong impression this slide can create |

## 5. External-material position

**All fourteen slides are deliverable from repository source alone.**

Module 2 requires **no external evidence whatsoever** — no project image, no CDE
view, no model view, no screenshot. The module's subject is functions and
authorities, and the controlled sources state them in text.

Two slides would be **actively harmed** by external material: `M02-S07` (platform
imagery implying a running coordination process) and `M02-S10` (a permissions
view implying access confers authority).

**Twelve diagrams, seven tables, two document extracts, one layout spec.** Tables
are used wherever a diagram would imply a hierarchy, a sequence or an authority
that the sources do not establish — Slides 6, 12 and the comparison half of 13
in particular.

## 7. Slides where the visual cannot stand alone

Ten of fourteen need speaker commentary to be safe rather than merely clearer.
In six cases the commentary carries a governance statement the visual cannot:

| Slide | What the speaker must supply |
|---|---|
| 1 | That the three accidental routes are generic conditions, not Harrismith history |
| 3 | Both halves of the functions-before-names argument |
| 6 | That the function is defined, not diminished |
| 7 | That the coordination process is **not evidenced as configured or running** |
| 11 | That "blocked" means nobody holds it — not that someone else does |
| 13 | That documented is not implemented |

**A deck circulated without a presenter would misrepresent all six.** If handout
distribution is ever proposed, these need written notes attached.

## 8. Mandatory warnings — all fourteen slides carry one

Unusually, **every slide in Module 2 has a build requirement that must not be
dropped**. The module is about authority, and almost every visual form available
carries an implicit authority claim — hierarchy, sequence, completeness or
staffing. The warnings in §§2–4 are what keep each form honest.
