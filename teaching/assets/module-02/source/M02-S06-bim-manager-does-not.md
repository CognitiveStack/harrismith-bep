## 1. Layout — balanced two-column

```text
┌────────────────────────────────┬────────────────────────────────┐
│  THE BIM MANAGER FUNCTION      │  NOT AUTOMATICALLY HELD        │
│  (equal width)                 │  (equal width)                 │
├────────────────────────────────┼────────────────────────────────┤
│  Maintains the BEP governance  │  Design approval               │
│  framework                     │                                │
│  Maintains the CDE strategy    │  Contractual decisions         │
│  Maintains the responsibility  │  Publication / exchange        │
│  architecture                  │  authority  [UNRESOLVED]       │
│  Manages governance decisions  │  Recipient acceptance          │
│  and change                    │  [UNRESOLVED]                  │
│  Performs governance assurance │  The Appointing Party or Lead  │
│                                │  Delivery Party function       │
└────────────────────────────────┴────────────────────────────────┘
```

**Table form, not Mermaid.** A flowchart would imply a relationship between the
columns; there is none. They are two lists about one function.

## 3. Three visual requirements

| # | Requirement |
|---|---|
| 1 | **Equal column width and weight.** No greying, no smaller type, no "but…" framing on the right |
| 2 | **Publication and acceptance marked `UNRESOLVED`**, not merely listed. Marking them as this function's exclusion alone implies somebody else holds them |
| 3 | **Distinguish the three classes** where a challenge is likely — direct exclusion, supported interpretation, unresolved authority. A small marker or footnote suffices |

## 4. The closing position — do not omit

BEP §5.5 supplies the sentence that keeps the slide from reading as a demotion:

> Where the BIM Manager identifies a problem outside the function's authority,
> the route is to **raise and escalate it, not to decide it**.

That is a defined route, not an absence of one.

## 5. Required message

> Expertise in BIM does not create contractual, technical or publication
> authority.

**Teaching synthesis.** The individual exclusions are directly sourced; this
sentence generalising them is not source wording. Label or footnote.

## 6. Simplification and omission

| Simplify | Omit |
|---|---|
| Five rows per column | Any exclusion not verified in the source |
| Three classification markers, small | The publication-planning history; the AG-series |
| — | Any holder name |
| — | Any visual device that diminishes the left column |

## 7. Overclaim risk

**Low in content; moderate in tone.** The content is sourced. The risk is a slide
that reads as *the BIM Manager does very little* — which is not what the sources
say and not what the module argues. Authority here is **defined, not
diminished**, and a defined boundary protects the holder as much as it constrains
them.
