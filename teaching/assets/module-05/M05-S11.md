## 1. Purpose and five-second takeaway

**Purpose.** Hold the boundary: an event **uses** a transition without **being** one

**Five-second takeaway.** *Only two steps change the state — and one of them is blocked.*

**Why this form.** Two tracks make the categories **structurally** separate. A broken connector shows the block **without removing the dependency**.

**Simplification rule.** Step descriptions may reduce to their kind word. **The `T1`/`T4` marking, the broken connector and the four-object strip may not be dropped.**

## 4. Fixed layout

**Two horizontal tracks that never merge and never share a box.**

**Upper track:** three event concepts.

**Lower track:** the eight controlled steps, with **`T1` and `T4` visually marked
as state transitions** and the other six marked **in words** as *action*, *use*,
*event*, *event*, *decision / status*, *rework*.

**Vertical dependency connectors** run from each event to the steps it uses:

| Event | Uses |
|---|---|
| `TRN-E01` | `T1`, then `T3` |
| `TRN-E02` | `T8`, then `T1` and `T3` |
| `TRN-E03` | `T4` — **connector drawn broken** |

**A right-hand strip** shows the four distinct objects.

## 5. Exact visible wording

**Every string below is mandatory on the slide.**

- `An event uses a transition — it is not that transition`
- `Only T1 and T4 change the information state`
- The **kind** of each of the eight steps
- **`T4 — BLOCKED · no available authorising function`**
- **`Information remains Shared`**
- The four §10.11 definitions — Published, Delivered, Received, Accepted

Four-object strip `x = 724–912`, `y = 110–380`.

**The tracks never merge and never share a box.**

## 7. Connector semantics

**Vertical connectors mean "uses / depends upon" — never identity.**

**Each is labelled `uses`.**

**No equals sign, no double-headed arrow, no shared node.**

**The `TRN-E03` connector is drawn with a visible break and labelled `BLOCKED`.**
No route continues past it.

**No arrow runs along either track** — there is no `T1`→`T2`→…→`T8` sequence, and
no arrow between the three events.

## 8. Status and warning treatment

**Mandatory warning: **`T4 — BLOCKED`** and **`Information remains Shared`****

**Two labels are mandatory:** `T4 — BLOCKED` and `Information remains Shared`.

The broken connector is not decorative — it is the only element that shows the
dependency existing **and** being unusable at the same time.

`T5`, `T6` and `T7`, if shown, must carry *state unchanged*.

**Status is carried by words, never by colour alone.** Minimum visible type
**14 pt**; principal labels **≥ 18 pt**; text contrast **≥ 4.5 : 1**; border and
connector contrast **≥ 3 : 1**.

## 10. Mandatory omissions

- **No arrow between the three events**
- **No `T1`→`T2`→…→`T8` sequence arrow**
- **No Delivered, Received or Accepted state box**
- No completed route past `T4`
- No equals sign, merge or shared node between the tracks

## 11. Accessibility and projection requirements

**Reading order:** events → steps → connectors → four objects.

**Connector labels are read aloud.** The break must be **described as blocked**,
not left to visual inference — a gap in a line is invisible to a screen reader.

**No information is carried by colour alone.** Connector meaning is carried by
**form and label**. Warnings remain legible at projection scale.

## 12. Screen-reader or presenter-notes description

> *Two parallel tracks. Upper: three delivery-event concepts. Lower: eight controlled steps, of which only T1 and T4 are marked state transitions; T2 is a receiving-team action, T3 a use or context, T5 and T6 events, T7 a decision or status, T8 rework. Vertical connectors labelled 'uses' join TRN-E01 to T1 and T3; TRN-E02 to T8, T1 and T3; and TRN-E03 to T4. The TRN-E03 connector is drawn broken and labelled blocked: T4 has no available authorising function and information remains Shared. A side strip lists four distinct objects — Published, Delivered, Received, Accepted — and states that Delivered, Received and Accepted are not information states.*

## 13. Producer-failure test

**Does any connector look like an equals sign or a merge?** If yes, redraw.

**Is there a box labelled Delivered, Received or Accepted in the state track?** If
yes, **STOP**.

**Is the `TRN-E03` connector visibly broken and labelled?** If it reads as a
normal edge, redraw.

## 14. STOP conditions

**Stop and refer back to the accepted plan if this visual would:**

- Identify an event with a transition
- Create a Delivered, Received or Accepted **state**
- Open `T4`
- Progress information beyond **Shared**
