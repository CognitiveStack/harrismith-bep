## 1. Purpose and five-second takeaway

Convert the module into **questions Triviron must answer before configuring anything**.

**If the audience takes one thing from this visual in five seconds:**

> These are the decisions. Make them before you configure anything.

## 2. Source and authority basis

**No Triviron source exists.** Nothing on this visual is a Triviron fact, and **no governance or implementation status is asserted for the project** — it has no entry in any register, because no controlled source describes it. It is recorded as **undescribed**, which is a different thing from unresolved.

**The question structure is `INTERP`**, drawn from the Harrismith material the module has already taught: what a CDE governs (`S1` §6.1), states and permitted use (`S1` §6.3), the two unresolved authorities (`S1` §9.7, §9.8), the unestablished standards (`S1` §11.3, §11.4), the direction of authority (`S1` §5.9, §12.6, §12.8), and the conditions `CGD-C01`–`CGD-C08`.

**Harrismith's blocked `T4` is the *reason a question is asked*** — not a prediction about a project nobody has described.

Source identifiers `S1`–`S14` are defined in
[`source-inventory.md`](../../../module-04-cde-workflows-and-information-states/source-inventory.md).
Classification follows
[`source-map.md`](../../../module-04-cde-workflows-and-information-states/source-map.md) §1.

## 4. Fixed layout

**Five numbered question groups**, in order, top to bottom.

**The two compulsory authority questions sit together, set apart, in a bordered block** placed after group 3.

**The end state sits at the foot**, beneath a rule, in neutral styling.

**The five groups keep their order.** **Purpose precedes states; states precede transitions; configuration is last — because the order *is* the argument.**

**This slide will look sparse, and a producer will want to balance it.** An illustrative answer, a sample state model, a suggested platform, a progress bar under the end state — **each of those invents the project.** **The sparseness is the deliverable.**

**The fixed form, carried from the `W14` specification:**

```text
  1  CDE PURPOSE AND SCOPE
     What information? Which teams? Which uses? Which phases?
     What evidence that the process operates?

  2  INFORMATION STATES AND PERMITTED USE
     Which states? What is each for? Who may rely on each?
     Conceptual, physical or both? Which folder relationship?
     How will folder location be prevented from meaning state?

  3  TRANSITIONS, GATES AND AUTHORITY
     Which actions change state? Who initiates? Who checks?
     Who authorises? What if an authority is unassigned?
     Which transitions must stay blocked?

           ┌───────────────────────────────────────┐
           │  Who holds publication authority?     │
           │                                       │
           │  Who holds acceptance authority?      │
           └───────────────────────────────────────┘
                    ▲ asked, and not answered

  4  NAMING, REVISION, SUITABILITY AND METADATA
     Which standard? Which convention? Which codes? What schema?
     Who assigns and checks? How are codes kept distinct from
     evidence that the process occurred?

  5  PLATFORM CONFIGURATION AND IMPLEMENTATION EVIDENCE
     Which platform? Who may configure? How authorised?
     How are deviations recorded? How is configuration verified
     against governance? Who declares the CDE ready for use?

  ───────────────────────────────────────────────────────────
       CDE configuration basis — not yet established
```

## 8. Status and warning treatment

**No governance status and no implementation status is asserted for Triviron**, because no controlled source describes the project. **This absence is stated rather than left blank** — it is the visual's central discipline.

**The two authority questions are neither answered, hinted at, nor paired with a candidate role.** `S1` §9.7 already excludes four by name; **a fifth must not appear.**

**`CDE configuration basis — not yet established` appears as the end state, in neutral styling.** **No warning colour, no icon, no date and no owner.** It is **a correct starting position, not a defect.**

**No Harrismith status is transferred onto Triviron.**

## 9. Build or reveal sequence

**Group-by-group reveal is permitted**, in the fixed order, because the order is the argument and revealing it in order reinforces rather than distorts it.

**Two constraints:** the **authority block appears with group 3**, never later and never as a separate reveal that turns it into a punchline; and **the end state appears last, without emphasis** — no zoom, no colour change, no sound.

**If a static export is produced, it is the final frame only.**

## 10. Mandatory omissions

**Every Triviron fact** — jurisdiction, project type, client, asset, procurement route, appointments, named roles, platform, folder structure, states, naming, codes, schema, dates, teams · **every answer, default, placeholder, example and recommendation** · any answer column · any grey placeholder answer · any platform recommendation · any status colour · any completion tick · any final configuration diagram · any progress bar under the end state · any Harrismith status transferred onto Triviron.

## 11. Accessibility and projection requirements

- **Every item is a question, and reads as one** — the question mark is the accessibility feature as well as the control.
- **The authority block's separation is carried by its border and by the marker text**, not by position alone.
- **The end state is neutral in colour and in text.** It must not be styled as an alert, and it must not be the only element in an accent colour.
- **Reading order** — group 1, group 2, group 3, the authority block and its marker, group 4, group 5, then the end state.
- **Type: group headings 16 pt, questions 14 pt minimum, authority questions 18 pt, end state 18 pt.**
- **Contrast ≥ 4.5:1** for text; **≥ 3:1** for the authority block border and the rule.
- **Do not reduce the question text below 14 pt to fit a sixth group.** There is no sixth group.

## 13. Producer-failure test

The visual fails if a viewer can reasonably conclude:

- any **Triviron fact** has been asserted;
- either **authority question has been answered**, or a candidate suggested;
- a **platform has been recommended**;
- the end state is a **failure or a warning**;
- Harrismith's **structure or status transfers** to Triviron.

## 14. STOP conditions

**Stop production and return to the `W14` specification if:**

- **any item on the slide is not a question**;
- either compulsory authority question is answered, hinted at, or paired with a candidate role;
- **either compulsory question is removed** from the bordered block;
- an answer column, placeholder answer or worked example is added;
- a platform is named or recommended;
- a Triviron fact of any kind appears, including a placeholder project name or a date;
- the five groups are reordered, or configuration is moved earlier;
- the end state acquires a warning colour, an icon, a date, an owner or a progress bar;
- a sixth group is added to balance the layout.

## 15. Native PowerPoint reconstruction notes

**Reconstruct with native PowerPoint shapes, tables and text boxes.** **No image
is imported, and no diagram-rendering engine is used.**

**Five text blocks, one bordered rectangle, one rule, one text box. No SmartArt, no icons.**

1. Groups as five text blocks in fixed order, each with its number and heading. **Do not convert them to a SmartArt list** — the numbered-list layouts add chevrons, which make the groups a process.
2. Authority block as a plain rectangle after group 3, **containing only the two questions**, with the marker text box beneath it.
3. **Do not fill the authority block with an accent colour.** It is set apart by its border, not by emphasis.
4. Rule, then the end state as a centred text box at 18 pt in **body colour** — not the theme's alert or accent colour.
5. **Insert no icon of any kind**, and **no progress indicator** under the end state.
6. **Leave the whitespace.** If the slide looks empty, that is the correct result; do not add a second column, an image or a summary box.
7. If animating, reveal group by group in order, **with the authority block appearing as part of group 3** and the end state appearing last **without emphasis effects.**
