# Module 3 — Presentation Assembly Package

**Status:** Production handoff. **Not governance. Not the final presentation.**

---

## 1. What this package is

A concise, traceable specification from which the fourteen-slide Module 3
PowerPoint can be built **without reinterpreting the long-form source**.

Module 3's teaching content and visual source together run to roughly **9,000
lines** across outline, speaker notes, exercises, source map, external-source
register, visual plan, asset register, slide map and fourteen visual-source
files. That volume is correct for developing and defending material whose subject
is a copyrighted standard the programme does not hold. **It is the wrong input for
a producer building slides.**

This package compresses it to what a producer needs: what goes on each slide,
what the presenter says around it, which visual belongs there, and — for this
module above all — **what must not be tidied.**

## 2. What this package is not

| It is not | Because |
|---|---|
| An ISO document, or a statement of ISO requirements | **The standard has not been read for this programme.** What is taught is public scope, UK guidance and project evidence |
| A controlled BEP deliverable | It carries **no project governance authority** and decides nothing |
| A replacement for the teaching source | The detailed source remains authoritative; this is a derived view |
| The final PowerPoint | **PowerPoint production follows this increment**, performed by ChatGPT after this package is reviewed and accepted |
| A rehearsal record | **No rehearsal has occurred and no timing has been measured** |
| A conformity assessment | **No conformity conclusion is supported, in either direction** |
| A publication artefact | Publication automation remains **paused** |

**Where this package and the teaching source differ, the teaching source is
correct** and this package is the thing to fix.

## 5. Seven things a producer must not do

| # | Do not | Because |
|---|---|---|
| 1 | **Reconstruct an ISO figure** — including from memory, from search results, from a third-party version, or as a "simplified" derivative with changed styling | ISO standards are copyrighted, **and nobody here has seen the figures**. A reconstruction of a figure nobody has looked at is an invention wearing a citation |
| 2 | **Turn public scope into requirements** | The registered sources supply **scope and status**, not obligations. Adding detail to fill a column is fabrication |
| 3 | **Remove a UK jurisdiction label** | UK BIM Framework material is **implementation guidance, not the ISO text**, and it is not automatically applicable in South Africa |
| 4 | **Convert an analogue into an alignment claim** | Harrismith **illustrates** principles. It evidences nothing about the standard |
| 5 | **Complete a blocked or empty visual** | Five visuals are deliberately incomplete. **Each "fix" asserts something the evidence does not support** — see §6 |
| 6 | **Populate a Triviron answer** | **No Triviron project fact exists.** Slide 14 is questions only |
| 7 | **Add a compliance colour, tick, score or percentage** | A score asserts an assessment method, an evidence base and a competent assessor. **None exists** |

## 6. The five that must not be tidied

**These are automatic production requirements, not stylistic preferences.**

| Slide | Stays | A "fix" would claim |
|---|---|---|
| **8** | Rows **offset and unpaired** | That `Lead Delivery Party` is *lead appointed party* |
| **10** | `Shared → Published` **blocked** | That a workflow operates which has **no authorising function** |
| **11** | Evidence fields **empty** | That something was delivered. **Nothing has been** |
| **12** | Evidence **incomplete**; assessment **outside** the chain | That the chain leads to conformity |
| **13** | Direct-evidence band **near-empty, one item** | That alignment is broader than one declaration of influence |

**Slide 8 and Slide 13 can be failed by layout alone, with no word spoken.** They
carry the module's highest overclaim risk for exactly that reason.
