## 2. Prohibited source routes

**No authorised route exists for any of the following, and none may be drawn,
taught or implied:**

```text
Working Process ──✗──► governance
   (a working outcome — including a working `APPROVED` — reaches governance
    only through the separate governed decision route, recorded in the
    Governance & Decision Register)

Workshop output ──✗──► BEP / matrix / schedule / appendix update
   (updates occur only through authorised governance decision and the
    authorised implementation route, then verification)

Harrismith value ──✗──► Triviron answer
   (the accepted Module 7 STOP rule survives into every workshop stage)

Module 8 teaching synthesis ──✗──► Triviron governance
   (a teaching method, however complete, establishes nothing for Triviron)
```

## 3. Reading rules

- A source's position on this map never upgrades its authority: the
  working-pattern family remains `Authority: None` wherever it appears.
- The publication-planning edge carries the **agenda analogue only** — no
  publication-specific governance (PM/PE/PAD constructs, conditions,
  arrangements) transfers into workshop teaching.
- The Module 7 register is an **input**, never a Module 8 drafting surface;
  Module 8 must not modify it or any Module 7 teaching source.
- Class F (controlled Triviron sources) does not appear as a feed because it
  is **`NONE IDENTIFIED`** — if a controlled Triviron source ever enters
  through a governed route, its handling belongs to Module 7's framework and
  future governed increments, not to a workshop conversation.

## 4. Vocabulary separation

Four vocabularies touch Module 8. **They are separate systems and are never
merged or harmonised, even where labels collide:**

| System | Terms | Owner |
|---|---|---|
| Module 7 translation classification | `METHOD` · `EVIDENCE REQUIRED` · `DECISION REQUIRED` · `PROPOSAL` · `ESTABLISHED` | Accepted Module 7 schema §3 |
| Module 7 status vocabulary | `NOT YET ESTABLISHED` · `NOT ESTABLISHED` · `UNRESOLVED` · `TBD` · `PROPOSED — NOT APPROVED` · `ESTABLISHED` | Accepted Module 7 schema §4 |
| Working Process vocabularies | Seven contribution types (WP2); working statuses `NEW` … `CLOSED`, including `DECISION REQUIRED`, `APPROVED`, `DEFERRED` (WP9) | `working/README.md` — `Authority: None` |
| Governance & Decision Register vocabulary | `OBSERVED FACT` · `TRAINING ASSUMPTION` · `PROPOSED GOVERNANCE` · `APPROVED GOVERNANCE` · `UNRESOLVED DECISION`, and its own entry statuses | The controlled register |

**Label collisions to keep apart:** a Working Process **`DECISION REQUIRED`**
is a working status, not the Module 7 classification of the same name; a
Working Process **`APPROVED`** is *never* `APPROVED GOVERNANCE` — the Working
Process says so itself; a Working **`DEFERRED`** is not a Module 7 `TBD`;
and no platform status label belongs to any of these systems.
