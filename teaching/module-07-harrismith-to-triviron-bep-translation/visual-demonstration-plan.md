## 2. Module-wide visual rules

### 2.1 Reference canvas

Adopted unchanged from the accepted Module 6 precedent
([`../module-06-coordination-review-approval-and-assurance/visual-demonstration-plan.md`](../module-06-coordination-review-approval-and-assurance/visual-demonstration-plan.md)
§2.2). Disk inspection shows no reason to depart from it.

| Parameter | Requirement |
|---|---|
| Canvas | **960 × 540 pt**, 16:9 |
| Origin | Top left; `x` increases right, `y` increases down |
| Title zone | **`y = 0–72` — reserved.** No content beneath the title baseline |
| Side margins | **≥ 48 pt** — content span is therefore **exactly 864 pt**, `x = 48–912` |
| Lowest permitted object edge | **`y ≤ 520`** |
| Minimum visible type | **14 pt** |
| Principal labels | **≥ 18 pt** |
| Status, classification and boundary words | **≥ 18 pt** — never reduced to fit |
| Text contrast | **≥ 4.5 : 1** |
| Border and connector contrast | **≥ 3 : 1** |

### 2.2 Coordinate and geometry convention

Every geometry statement uses **absolute canvas coordinates in points**, written
as `x = a–b`, `y = c–d`. Every specification states enough spatial relationship
to prevent semantic drift: **relative position · equal or unequal visual weight ·
separation · adjacency · reading order · which objects may connect · which
objects must never touch, merge or share a border.**

### 2.3 `GEOMETRY ARITHMETIC SELF-CHECK` — mandatory

**This rule is preventive. The Module 6 experience — five mathematically
inconsistent geometries found at governance review and repaired in `T6-G-R` —
must not be repeated as a later repair in Module 7.**

**Every specification carries an explicit arithmetic self-check field**, and the
check must be satisfied **before `T7-K` visual-source production begins**.

| Rule | Requirement |
|---|---|
| **G1** | Any row of components must satisfy `Σ component widths + Σ gaps = the stated total span`, calculated in the specification |
| **G2** | Any column of components must satisfy `Σ component heights + Σ gaps = the stated total height`, calculated in the specification |
| **G3** | Where components are stated to be **equal**, the arithmetic must produce **exactly equal** values — a stated equality that does not divide exactly is a defect |
| **G4** | Where an exact division is impossible, the nominal value is stated to three decimal places and the remainder is **distributed**, never independently rounded per component |
| **G5** | **No unexplained overlap.** Two objects may share coordinates only where the specification says so and says why |
| **G6** | **No off-canvas object.** Every coordinate lies within `x = 0–960`, `y = 0–540`, and every content object within `x = 48–912`, `y = 72–520` |
| **G7** | **No boundary, status or STOP warning may be positioned outside the visual region it governs.** A warning about a panel sits inside or immediately beneath that panel's own frame |
| **G8** | A producer who cannot reproduce a stated arithmetic result **stops and refers back**. A producer may not silently adjust coordinates to make a layout fit |

### 2.4 Status visibility

**Every visual that shows a translation classification, a register status, an
evidence position, an authority position or a typed absence must display it in
words, on the slide.**

**Status may never exist only in the presenter notes. Status meaning may never
depend on colour alone. Every status is carried by a word.**

The vocabularies available to Module 7 visuals, kept strictly apart (§2.5):

| System | Values | Register field |
|---|---|---|
| **Translation classification** | `METHOD` · `EVIDENCE REQUIRED` · `DECISION REQUIRED` · `PROPOSAL` · `ESTABLISHED` | field 10 |
| **Status** | `NOT YET ESTABLISHED` · `NOT ESTABLISHED` · `UNRESOLVED` · `TBD` · `PROPOSED — NOT APPROVED` · `ESTABLISHED` | field 18 |
| **Evidence availability** | `NONE IDENTIFIED` | field 8 |
| **Candidate-decision position** | `NOT POPULATED — PROPOSAL STAGE NOT AUTHORISED` | field 11 |

**No new status, classification or absence term may be invented for visual
convenience**, and **no visual is required to use every term**. Each
specification names the ones it must carry.

### 2.5 Classification is not status — mandatory separation

**`ESTABLISHED` appears in both vocabularies with different meanings.** The two
systems are therefore separated by construction, not by caption:

| Rule | Requirement |
|---|---|
| **C1** | **Never place both systems on one progression axis**, one row, one strip, one column or one ramp |
| **C2** | **Never use one shared colour ramp**, weight ramp, size ramp or numbering across the two systems |
| **C3** | **Never imply either system is a maturity ladder**, a timetable, a pipeline or a score |
| **C4** | **Wherever both appear, each is independently labelled** — `classification` and `status` written as words beside their values |
| **C5** | A row that is validly `METHOD` **and** `NOT YET ESTABLISHED` must be drawable without contradiction. Any layout in which those two values look inconsistent has failed |
| **C6** | The five classifications are the **schema enumeration order**, and any visual showing them must say so in words: **`enumeration order — not progression`** |
| **C7** | `ESTABLISHED` may never be styled as a destination, endpoint, goal, right-hand terminus or filled state in either system |

### 2.6 Typed-absence treatment

**`NONE IDENTIFIED` is not `NONE EXISTS`.** A census finding about this
repository is never a claim about the world.

| Rule | Requirement |
|---|---|
| **A1** | A zero, an absence or an unknown is **neutral and explicit** — a stated word in a normally weighted object |
| **A2** | **No absence may be styled as failure**, deficiency, defect, negative score, rejected state, red alarm, warning colour, strike-through, greyed-out state, empty progress bar, unticked box or missing-data placeholder |
| **A3** | **No zero may appear inside a progress indicator**, percentage, gauge, meter, tally toward a target, or a container whose other cells are filled |
| **A4** | A cell reading `0` must carry, in words, **why it is zero** — for Module 7 that is `prerequisite evidence not identified`, never `not yet achieved` |
| **A5** | `NONE IDENTIFIED` must appear with its qualifier **`NONE IDENTIFIED ≠ NONE EXISTS`** wherever a reader could take it as a claim about reality |
| **A6** | The four status terms are **semantic states, never stages.** No arrow, no ordering, no numbering, no left-to-right advancement among them |
| **A7** | `NONE IDENTIFIED` (evidence availability, field 8) and the field-18 statuses are **different registers of absence** and are never drawn on one axis |

| **S2** | Every Triviron object drawn is a **question, an evidence requirement or a typed absence** — never an answer |
| **S3** | Source classes A–F ([`source-inventory.md`](source-inventory.md) §1) may be named on a slide; **class F is always shown as `NONE IDENTIFIED`** |
| **S4** | **No Harrismith source may be drawn as establishing a Triviron fact.** None can |

### 2.9 Native vs external imagery

**External imagery: `NONE REQUIRED` — for all fourteen visuals.**

Prohibited throughout: photographs · Autodesk, ACC, Forma, Revit or Navisworks
screenshots · any platform or product screenshot · document screenshots · model
screenshots · company or product logos · third-party images · downloaded icons ·
external SVG · icon-library assets · downloaded diagrams · interface replicas ·
any network-dependent asset.

**Why.** Module 7's entire subject is that **no controlled Triviron source is
identified**. A platform image, an interface capture or a document photograph
makes an arrangement look concrete and adopted; no caption can withdraw that as
persuasively as the image asserts it. **`M7-S03` prohibits attributing any named
platform to Triviron**, and an image is the fastest route to breaching it.

**Repository-owned text and register excerpts may be specified** — quoted as
native text, in native text boxes, with their exact wording, classification and
status. **A quotation is not a screenshot: it is retyped native text.**

### 2.11 Visual form

**Default and expected form: `NATIVE ORIGINAL DIAGRAM` — natively
PowerPoint-reconstructable layout.**

**Default and accepted source class for all fourteen visuals:
`NATIVE ORIGINAL DIAGRAM`.**

Permitted: text boxes · rectangles and simple native shapes · straight lines and
simple labelled connectors · native tables · fills and borders · native warning
strips · native call-outs · deliberately incomplete grids · native editable
symbols.

Prohibited: **SmartArt** · **Mermaid** · imported infographics · automatic
diagram or graph layout · automatic process diagrams · imported PNG, JPG or SVG ·
rasterised text · decorative three-dimensional effects · software-interface
replicas · external renderers · any rendering dependency.

**Mermaid risk test — applied separately to every visual.** An automatic-layout
form is prohibited wherever the layout engine could falsely imply **hierarchy ·
adoption · content transfer · a completed decision · an automatic progression
from evidence to decision · a maturity sequence · a populated Triviron answer ·
an authority holder · a scheduled event.**

**Result: `Mermaid PROHIBITED` for all fourteen.** Every Module 7 visual carries
at least one of those hazards, and most carry several.

### 2.12 Connector semantics

**Connector presence is a governance-sensitive visual choice, not a styling
choice.**

| Rule | Requirement |
|---|---|
| **K1** | **Every connector's meaning is stated in the specification and expressible in one sentence in words.** A connector whose meaning cannot be stated is deleted |
| **K2** | **No connector may run from a populated Harrismith object to a Triviron object of any kind.** There is no `HARRISMITH VALUE → TRIVIRON VALUE` edge anywhere in Module 7 ([`source-map.md`](source-map.md) §1) |
| **K3** | **Slide 2 uses zero connectors between its two principal columns.** No arrow, no bridge, no line, no shared border, no implied pairing between rows of the two columns |
| **K4** | Analytical arrows are **explicitly labelled as analytical / process-of-reasoning arrows** — they record the order in which the problem is worked. **Nothing flows along them** |
| **K5** | **STOP boundaries interrupt flow visually.** No connector may cross, enter, leave or pass behind a STOP object |
| **K6** | **No arrow may imply automatic progression from evidence to a decision** |
| **K7** | **No arrow may imply automatic progression from a workshop to a BEP update** |
| **K8** | A conditional step is drawn with its condition **in words on the object**, never as an unconditional arrowhead |
| **K9** | **No connector may terminate on an empty, absent or zero-valued object** — that reads as a route to an answer |
| **K10** | Connector direction and meaning are carried by **label and arrowhead**, never by colour |

### 2.13 Visual economy

**The accepted slide copy is content-complete. Much of it is too dense to
reproduce visually.** Each specification therefore identifies:

- **the principal visible relationship** — the one thing the layout must carry;
- **what may be abbreviated** — usually evidence-kind lists and examples;
- **what must remain verbatim** — classification words, status words, `NONE
  IDENTIFIED`, `NOT YET ESTABLISHED`, `NOT POPULATED — PROPOSAL STAGE NOT
  AUTHORISED`, the STOP wording, the exclusion wording, and the qualifiers
  `only`, `not automatically`, `if authorised`, `only when earned`;
- **what belongs only in presenter notes**;
- **what may be grouped**;
- **what must never be compressed** — every load-bearing distinction, count,
  classification, status and typed absence.

**A specification must not attempt to put every source sentence on the slide. It
must preserve every load-bearing distinction, count and status.**

### 2.14 Accessibility

Every specification carries: **logical reading order · a screen-reader
description · status and classification meaning in words · no information by
colour alone · the minimum type requirements of §2.1 · a projection-readability
requirement · connector meaning carried by direction and label · warnings that
remain legible at projection size · an alternative verbal description of the
visual's principal relationship.**

**Anything a sighted reader takes from separation, enclosure, weight, offset or
position must also be said in words**, because none of those survive audio.

**Governance boundaries must be readable, not decorative.** No boundary,
exclusion or STOP wording may be set below 18 pt, placed in a corner, styled as
legal small print, or relegated to a footnote. **If space is short, cut content
text — never boundary text.**

### 2.15 Producer reconstruction

**Although `T7-J` creates no PowerPoint, every visual is specified so that a
later producer can construct it from native editable PowerPoint objects alone.**

Every structural element must be achievable using: **text boxes · native shapes ·
lines and connectors · tables · fills and borders · native editable symbols.**

**Not required anywhere: imported PNG · SVG · screenshot · rasterised text ·
external icon asset · Mermaid render · any external or network dependency.**

Each specification states its **native reconstruction method** as an explicit
object inventory.

### 2.17 Overclaim and failure testing

**Every specification carries a slide-specific producer-failure test** (§2.18)
in addition to these module-wide tests, which apply to all fourteen:

| Test | Failure condition |
|---|---|
| **F1 — the invented-answer test** | Show the finished slide to a reader and ask: *does Triviron have an answer here?* Any answer other than *no, and none is claimed* is a failure |
| **F2 — the ladder test** | Ask a reader to put the classifications, or the statuses, in order. If they can, and believe the order is meaningful progress, the layout has failed |
| **F3 — the absence test** | Ask a reader whether the zeros mean something went wrong. If *yes* or *unclear*, the typed-absence treatment has failed |
| **F4 — the transfer test** | Ask a reader what the arrows move. If the answer names any content, value or answer, the connector treatment has failed |
| **F5 — the governance test** | Ask a reader whether the slide shows how Triviron works. If *yes*, *probably* or *unclear*, the teaching/governance boundary has failed |
| **F6 — the geometry test** | Recompute every arithmetic statement in field 17. Any contradiction is a failure and the producer stops |

### The domain family — `M7V-05` to `M7V-11`

**Slides 5 to 11 form one repeatable family.** The shared three-card grammar is
specified **once**, here, and instantiated seven times. **Each instantiation
carries the full 34-field architecture**; fields that are wholly governed by the
family grammar say so and are not restated, and every field that is
slide-specific is stated in full on the instance.

**The family grammar is empty grammar. It carries no content, and no content
crosses between instances.**

#### F.1 — Fixed visual form (family)

**Three co-equal cards in one row, one card per accepted decision question, each
card carrying four stacked zones; beneath the cards a full-width exclusion
strip; beneath that a full-width boundary strip.**

**No card may contain a fabricated Triviron answer.** Every card holds a
**question**, an **evidence requirement**, an **evidence position** and a
**typed absence** — nothing else.

#### F.2 — Object hierarchy (family)

1. the three cards — **strictly co-equal** in width, height, border, fill and
   type; no card may be emphasised, widened, ordered first by weight, or styled
   as more advanced, more important or nearer to an answer;
2. the exclusion strip;
3. the boundary strip.

**The exclusion and boundary strips are principal objects, not footnotes.**

#### F.3 — The four card zones

| Zone | Holds | Rules |
|---:|---|---|
| **Z1 — question** | The `TDR-` identifier and the accepted decision question, verbatim | **Phrased as a matter to decide, never as an answer.** No card may rephrase a question into a statement |
| **Z2 — evidence required** | The **kinds** of controlled Triviron source that would be needed, from register field 7 | **Kinds only.** Never a guessed content, never a named document, never a named platform, never a named organisation. Where an evidence kind is itself a structural artefact — an organisation chart, a task-team structure, a container inventory — **it is named in words and never drawn** (`M7V-S02`, `M7V-S05`) |
| **Z3 — evidence position** | **`Triviron evidence currently available: NONE IDENTIFIED`** and **`NONE IDENTIFIED ≠ NONE EXISTS`** | Identical on all 21 cards. **Neutral weight. No red, no alarm, no strike-through, no empty-bar treatment** |
| **Z4 — classification and status** | Two **independently labelled** lines: **`classification:`** *value* and **`status: NOT YET ESTABLISHED`** | **Never one line, one axis, one badge, one colour or one ramp** (`M7V-S23`). The classification line reads **`EVIDENCE REQUIRED`** or, on the three accepted `METHOD` rows only, **`METHOD`** |

colour, a rank, a score or a badge shape**, and it never implies that the card
is more advanced than its two neighbours — **all three cards on a `METHOD`
slide remain co-equal**.
